Developer Guide

SDK Architecture & Engineering Guide

Principles, lifecycle contracts, concurrency guarantees, and integration patterns for building on Limoxel's Engineering Knowledge Infrastructure.

1. Architecture & The EKI Coordination Model

The Limoxel SDK acts as a thread-safe, programmatic client over the underlying repository indexing, AST parsing, graph engine, and reasoning subsystems. Consumers interact through the unified *sdk.Client coordinator, which exposes 11 domain-specific capability contracts.

// High-level architecture: Client exposes typed capability interfaces client.Repository() // RepositoryManagementContract: workspace sessions and metadata client.Files() // FileContract: discovery, classification, and file relationships client.Packages() // PackageContract: hierarchy trees and dependent metrics client.Symbols() // SymbolContract: lookup, reference sites, and inheritance client.Search() // SearchContract: multi-domain unified query engine client.Graph() // GraphContract: topological traversal and Mermaid/DOT exports client.Analysis() // AnalysisContract: architecture boundaries and health reports client.Navigation() // NavigationContract: go-to-definition and call hierarchies client.Reasoning() // ReasoningContract: blast radius and refactoring advice client.Events() // EventContract: asynchronous lifecycle event streaming client.Intelligence() // IntelligenceContract: unified multi-capability facade

2. Client Lifecycle & Workspace Initialization

Clients can be initialized with functional configuration options or directly for a local workspace path. Always register defer client.Close() immediately following initialization to release underlying indexers, memory caches, and background worker routines cleanly.

ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second) defer cancel() // Option A: Open local workspace directly client, err := sdk.OpenWorkspace(ctx, "/path/to/repository") if err != nil { return fmt.Errorf("failed to open workspace: %w", err) } defer client.Close() // Idempotent; guarantees clean resource teardown // Option B: Initialize with functional configuration options client, err := sdk.New( sdk.WithWorkspace("/path/to/repository"), )

3. Context Management, Deadlines & Cancellation

Every method in the Limoxel SDK requires a context.Context as its first parameter. All long-running operations—including repository indexing, deep graph path traversals, and whole-codebase architecture analysis—honor context cancellation immediately and clean up transient resources.

// Always supply bounded contexts to prevent runaway traversals ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second) defer cancel() paths, err := client.Graph().FindPaths(ctx, "pkg/auth", "pkg/storage", 5) if errors.Is(err, context.DeadlineExceeded) { log.Println("Graph traversal exceeded deadline; bounded search terminated safely.") }

4. Structured Error Handling & Error Categories

All errors returned by the Limoxel SDK implement the sdk.SDKError interface. Consumers can inspect error categories programmatically to differentiate between missing entities, invalid arguments, internal system faults, or lifecycle state violations without string parsing.

sym, err := client.Symbols().LookupSymbol(ctx, "NonExistentSymbol") if err != nil { var sdkErr sdk.SDKError if errors.As(err, &sdkErr) { switch sdkErr.Category() { case sdk.CategoryNotFound: log.Printf("Entity not found: %s", sdkErr.Message()) case sdk.CategoryInvalidInput: log.Printf("Invalid symbol query: %s", sdkErr.Message()) case sdk.CategoryInvalidState: log.Printf("Client is in invalid state: %s", sdkErr.Message()) default: log.Printf("SDK error [%s]: %s", sdkErr.Category(), sdkErr.Error()) } } }

5. Concurrency & Goroutine Safety

A single *sdk.Client coordinator is strictly thread-safe and designed for high-concurrency workloads. Multiple goroutines, HTTP worker pools, or analysis pipelines can share the same client instance concurrently without external mutex locks.

6. Semantic Versioning & Compatibility Policy

Limoxel adheres strictly to Semantic Versioning 2.0.0. Minor releases introduce backward-compatible capability additions, and patch releases introduce backward-compatible bug and security fixes. Public contracts under sdk/ maintain complete binary and source compatibility across all 1.x releases.
